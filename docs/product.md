# 个人主页产品说明

## production

### 用户是谁

希望了解 Dandi 的项目、思考和 AI 工作方式的个人主页访客。

### 核心价值

通过真实项目与时间线，让访客看到本人如何逐渐学会与 Agent 协作，以及产品判断和设计能力如何变化。

当前内容先沿本人提出的两条线组织：工程能力——把项目完成；AI 能力——把项目做漂亮。同一个项目可以支撑两条线，具体措辞先用历史证据提炼，再由本人认可。

### 产品原则

保留本人语气和具体经历；用真实版本与截图支撑叙述；区分口述经历、代码时间与上线状态；私有素材匿名展示。

### 不做什么

不把仓库清单等同于个人贡献，不编造遗忘的经历或量化成果，不将截图 mock 当成真实业务效果。愿景、当前实践与已验证结果分别表达。

### 用户体验路径

页面包含 Hero、Future of Work（含 Worket 实践）、Experiments 和 Writing。访客先看未来工作愿景，再从最新到最早的五个案例了解真实探索，最后阅读方法与思考。

## ux

### 设计原则如何回应以上要求

案例围绕背景、目的、做法与变化展开；同一项目允许展示多阶段界面。早期 UI 保留原貌，使进步有据可看。相关工具可关联阅读，避免割裂 GEO 的演进故事。

两条叙事分别选取交付和设计的具体转折；“漂亮”以界面对比、视觉规则和操作组织展开，不只给审美结论。候选串联文案与来源见 [两条成长线](experiments/two-tracks.md)。

当前 JetBao 本人认为已基本讲清，GEO 本轮讲述也已确认收束。GEO 先呈现事实原则、内容的服务对象与目的，以及方法论和场景包如何连接商业问题与单篇目标，再展开界面；按本人叙述组织思考顺序，具体版本仍由提交证据单独标记。

GEO 后续继续呈现自动化判断：Post 的系统重构与发布插件的半自动方案并列，说明本人怎样选择长期结构、最简可行方式与人工边界。实现、分支合并及实际发布分别核实，不把功能代码等同于业务完成。

Dashboard 接着围绕本人确定的两个点展开：Private 互动以真实设计迭代支撑 AI / 设计线，管理页新应用动态接入支撑工程线。先呈现本人判断与具体行为，再用固定版本证明，不把整个产品所有能力归为个人成果。

内容范围与进度见 [AI Experiments 索引](experiments/README.md)。

## 2026-11-09：本地直接编辑

本人要求在网页上直接修改文字。通过 `npm run preview` 打开本地页面，右下角“编辑文字”进入编辑模式，标题、段落、图注、日期和文字链接显示可编辑边框；点击对应文字即可修改。中文与英文分别保存，可在编辑中切换语言，不自动翻译或覆盖另一种语言。

“保存”或 Cmd/Ctrl+S 将修改写入项目的 `content.json`；“完成”先保存再退出。“撤销修改”恢复到上次保存，离开有未保存内容的页面会提示。保存失败保留当前修改，其他标签页已保存时提示冲突，不静默覆盖。支持纯文字粘贴及段落内换行，不提供版式、图片、链接地址或富文本编辑。

保存后的内容在刷新、重启预览和重新构建后保留。编辑工具只出现在本地预览中，静态构建仍为普通访客页面。Markdown 记录保留讨论来源与历史，网页手动修改不会自动回写成口述证据，也不会自动发布网站。

本轮验收：已在浏览器完成中英文分别修改、切换语言保留草稿、保存、刷新保留、撤销和“完成”保存退出；测试文字已恢复。390px 手机宽度下工具栏可用且无横向溢出。静态检查、持久保存集成测试与构建通过，浏览器无控制台错误。
