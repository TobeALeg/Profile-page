## 找回的本人历史对话

2026-08-28 的 Codex 原始会话明确对应 GEO Console / Mentti Post 工作面。以下是当时本人的具体判断，不是根据提交标题反推的动机。会话与行号详见 [Post 与插件证据](post-plugin-evidence-2026-10-08.md)。

- 内容稿让用户看到来源与分类，初稿箱是尚未发布稿件的视图，业务上是同一个对象。
- 要有已发布页面，记录渠道、公开 URL、发布时间和发布版本；稿件不复制、不搬动、不删除。按生命周期安排，是为了清楚看到工作量与下一步。
- 手写和导入对系统来说同属外部资料，不需要人为分成两套业务流程。
- 依赖需要一个唯一、通用、能流通的 ActiveSnapshot，避免各模块各管版本、临时拼凑。
- 插件辅助自动化部分发文章的过程；当时与系统独立，还需要接入及安装入口。
- 发布结果取决于 MultiPost 能拿到多少信息；拿不到充分信息时，可在一天后复查。
- 一次性迁移没有专门 Agent 做语义判断，建设长期固定流程得不偿失，选择确定性迁移后由本人判断和填充。

这组对话同时支持两类取舍：应当统一的内容、来源与状态要重构清楚；只发生一次或平台信息不足的环节，保留人工和复查。

## 插件的实现边界

插件对应独立的 `TobeALeg/multi-post` 仓库；沿用 MultiPost 的平台发布能力并增加 Mentti 集成。它与 GEO Post 工作面是两个代码责任范围，不能把沿用的全部渠道能力算成本人从零实现。

旧版辅助发布和 URL 回填，与后来的 V6 正式发布尝试桥接分别记录。插件能够减少部分操作；候选 URL、草稿保存、平台提交和公开发布是不同阶段。具体提交和分支状态见 [证据文档](post-plugin-evidence-2026-10-08.md)。

本轮核查的插件 V6 代码只在有 URL 时回传发布、审核或候选链接观察，不把类型中列出的全部状态及后台重启恢复都写成已实现。旧版默认不自动点击发布，但有绑定和 URL 时仍回填；这与本人半自动方案叙述相符。实际平台状态及已安装版本未查。
